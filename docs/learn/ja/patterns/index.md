# 実用パターン: 動くコードを、壊れにくい形にする

> **対象読者**: [はじめての Z-Ts](../start.md) と [アプリを作る](../tutorials/index.md) を終えた人。
> **所要時間**: 20 分（練習問題を除く）。
> **このページを終えると**: コマンド・状態・エラーの「書き方の選択肢」と、それを選ぶ基準を持てます。

チュートリアルのカウンターは**動く最小形**です。そこから少し育つと、必ずこうなります。

- コマンドが 1 画面 1 個に増え、同じ処理が 3 か所に散る
- 状態をどこに置くか毎回迷い、`global var` に逃げる
- エラーを文字列で返しはじめ、UI がその文字列を表示する

この章は、その 3 つ（**コマンド・状態・エラー**）と、その上にある**境界の引き方**を扱います。
どれも「動く」と「育つ」の差が出るところです。ライブラリの API は
[`reference/cli.md`](../../../reference/cli.md) と [API リファレンス](../../../api/index.html) が正本で、
ここは**選び方**の話です。

| ページ | 扱うこと | 練習 |
|---|---|---|
| [コマンドの設計](commands.md) | 粒度・引数・戻り値・命名。「動詞 1 つ = コマンド 1 つ」 | 3 問 |
| [状態の置き場所](state.md) | `*State` を引数で受ける。フロントと Zig のどちらが持つか | 2 問 |
| [エラーの設計](errors.md) | `error{}` の粒度、境界での検証、UI に出す翻訳 | 3 問 |
| [画面とロジックの境界](boundaries.md) | 楽観更新・二重送信・ローディング。1 画面 = 1 コマンドにしない | 2 問 |

## この章の読み方

各ページは同じ形です。

1. **動く例**（短い）
2. **育つ書き方 / 壊れる書き方**（表と、before → after のコード）
3. **なぜそうなるか**（1〜2 段落。ここだけ読んでも価値があるように書いています）
4. **練習**（`<details>` を開くと答え）

練習は**手を動かす**前提です。`zts init` したプロジェクトか、
[`examples/counter`](../../../../examples/counter/README.md) を開いて、その場で書き換えてください。
1 問 5〜10 分です。読むだけなら 20 分、全部やるなら 60 分を見てください。

> [!TIP]
> この章の後は [目的から引く](../guides/index.md) と
> [動くサンプル](../../../../examples/counter/README.md) が待っています。サンプルは**完成形**、この章は**途中で迷ったときの判断基準**です。

## 先に 1 枚で

| 迷い | 既定の答え | 例外 |
|---|---|---|
| コマンドを分けるか、引数で切り替えるか | **分ける**。名前が違えばコマンドも違う | 違いが「値」だけなら引数 |
| 状態は Zig とフロントのどちらに置くか | **正しさが要るなら Zig**、見た目だけならフロント | 入力途中の値はフロント（送る前） |
| エラーはどう返すか | `error{…}` を返し、UI がコードを文言に翻訳する | 期待される分岐（在庫 0 など）は戻り値に含める |
| 何個のコマンドを 1 画面に許すか | **操作の数だけ**。画面の数ではない | 読み取りは 1 つにまとめてよい |
| 検証はどこでするか | **境界で 1 回**（コマンドの先頭） | 型で表せるなら型にする |

次のページから、この表の各行を理由ごと開いていきます。
